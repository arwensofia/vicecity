# Module map of `SLUS_205.52`

Generated by `scripts/classify.sh` (Ghidra `ClassifyFunctions.java` + `tools/modules.py`).
Labels come from, in order of precedence:

1. `tools/module_overrides.csv` — hand-verified address ranges, each with its evidence.
2. Referenced strings (Sony `PsIIlib*` tags and `libxxx:` messages, RenderWare `$Id`, game prose).
3. Direct `syscall` use (only `libkernl` issues syscalls).
4. **Compiler fingerprint** — the width of the first `ra` / s-register spill in the prologue
   (`prologue` column of `classified.csv`). The three toolchains in this binary differ:

   | Fingerprint | Spills | Who |
   |---|---|---|
   | G | `sd ra`, `sq s*` (functions 16-byte aligned) | game code |
   | R | `sq ra`, `sq s*` | RenderWare 3.3 |
   | S | `sd s*` (8-byte alignment) | Sony libs, newlib, libgcc, libstdc++, DTS |

   Unlabeled G/R functions are seeded from it, and propagation never gives a function a
   label its fingerprint contradicts. Leaf functions have no fingerprint.
5. Propagation: a function sandwiched between two functions of the same module, or whose
   labeled callers all agree, inherits that label.

Function names for identified library code are applied to the Ghidra project from
`tools/library_names.csv` by `tools/ghidra/ApplyLibraryNames.java` (namespace per library;
guesses only as `guess:` plate comments).

## Identified libraries

Sony SDK 2.4 libraries are confirmed by `PsIIlib*` version tags in `.data`; data order
matches text order, which places the string-less ones. Key evidence per library (full
per-function evidence is in `tools/library_names.csv` and `tools/module_overrides.csv`):

- **libmc** — `sceMcInit` binds RPC `0x80000400` (mcserv) and checks mcserv/mcman versions; the
  wrappers call `sceSifCallRpc` with mcserv function numbers `0x01–0x15`, `0xFE`, matching the
  public numbering, and the game's memory-card debug messages at each call site agree
  (open/close/read/write/chdir/format/delete). `sceMcSync` polls `sceSifCheckStatRpc`.
- **libcdvd** — RPC clients `0x80000592` (init), `0x80000593` (S commands), `0x80000595`
  (N commands), `0x80000597` (search file), `0x8000059a` (disk ready); S-command numbers
  `0x01` ReadClock, `0x16` Break, `0x22` Mmode; `sceCdSt*` stream commands 1–9 behind one RPC
  helper. Only these entry points are linked — the game reads data through its own IOP
  stream module, not `sceCdRead`.
- **libipu** — `sceIpuStopDMA`/`sceIpuRestartDMA` save/restore DMA ch3/ch4 + `IPU_CTRL`/`IPU_BP`,
  `sceIpuSync` polls `IPU_CTRL.BUSY`; guess `sceIpuInit` (IPU reset + SETIQ/SETVQ/SETTH).
- **libscf** — `sceScfGetLanguage/Aspect/Spdif/TimeZone` decode the documented OSD config
  bitfields of `GetOsdConfigParam`, `DateFormat/SummerTime/TimeFormat` those of
  `GetOsdConfigParam2`; reads `rom0:ROMVER` via `sceOpen/sceRead/sceClose`.
- **libdev** (not libvu0) — the heavy-COP2 functions `0x110548`/`0x110628` are
  `sceDevVu0GetCnd`/`sceDevVu0PutCnd` (exact `sceDevVu0Cnd` layout: vf[32], status, mac,
  clip, R, I, Q, vi[16]); `Pause/Continue/Exec/GetTpc` drive FBRST/CMSAR0/TPC. No libvu0
  code was found.
- **libdma, libgraph, libsdr, libpad** — previously known; now fully bounded and named
  (`sceDma*`, `sceGs*`, `sceSdRemote*`, `scePadInit/PortOpen`).
- **libkernl** — 58 referenced syscall stubs in the table (names checked against the standard EE syscall
  table) plus labels on 65 unreferenced stubs; `DIntr/EIntr`, `SyncDCache/InvalidDCache`,
  `sceSifInitCmd/SendCmd`, `sceSifInitRpc/BindRpc/CallRpc/CheckStatRpc`,

- **DTS Interactive encoder** (third party) — its only callers are game audio functions that

## What this means for the runtime

- Hardware access is concentrated in a few libraries, so the runtime can replace those
  libraries' functions wholesale (high-level emulation) instead of emulating registers.
  `libmc`, `libcdvd`, `libsdr`, `libpad` and the fileio/IOP-heap parts of `libkernl` are thin
  SIF RPC clients: HLE at the `sceSifBindRpc`/`sceSifCallRpc` level or per API function.
- `libkernl`'s `_InitSys` installs kernel-mode patches from `.data` (`0x42de78+`) with
  `SetSyscall` and temporary syscalls `0x5A`/`0x5B`: the alarm syscalls `0xFC`/`0xFE` that
  the game uses via `SetAlarm` (252), TLB helpers `0x54–0x56`, and an OSD helper. These must
  be provided by the runtime's kernel HLE; the patch code must not be recompiled in place.
- Static constructors at `0x4a7880–0x4a90ff` run before `main` and must be included in the
  recompiled program (they were missing from the Ghidra function list until now).
- Graphics reaches the GS through DMA packets that RenderWare's `sky2` driver builds,
  with VU1 microcode doing transform/lighting (decision: PCSX2 GS + VU1 for now).
- Game code uses VU0 macro instructions heavily (~900, mostly vector/matrix math); these
  translate directly to NEON. The DTS encoder adds ~890 VU0 ops and uses VU0 micro mode.
